# Havemind 1.4.24

Editing the same note back and forth between two devices now converges in place
instead of producing a conflict copy on every exchange. Acknowledging a device's
own echo was recording the revision envelope hash into the synced base, a slot
that holds a plaintext hash, so the two could never match and every file that
device had pushed read as permanently diverged.

On the server, superseded revisions are retained rather than deleted. Deleting
them rejected a peer's next edit with MISSING_PARENT once its head had been
superseded, and cascaded away the revision's event row, leaving the event log
with holes that stopped clients from advancing. A repair script,
`apps/server/scripts/renumber-event-log.mjs`, restores a log damaged before this
release.

Privacy: Havemind makes network requests only to the self-hosted server URL a
user explicitly configures for a vault. It contains no telemetry or analytics.
