# Havemind 1.6.0

- Saving a local change is now a single write, so a crash or a full disk in
  the middle of a save can no longer leave a queued change half recorded.
- Large queued changes, such as a 25 MiB attachment, now wait in the device's
  local database instead of inside data.json.
- A corrupt sync state recovered from its backup right after the upgrade can
  no longer drop the list of files.
- The plugin moves its old file list over once on first start. Nothing to do,
  and no server change is needed. Devices on 1.5.9 and 1.6.0 sync normally.

Privacy: Havemind makes network requests only to the self-hosted server URL a
user explicitly configures for a vault. It contains no telemetry or analytics.
